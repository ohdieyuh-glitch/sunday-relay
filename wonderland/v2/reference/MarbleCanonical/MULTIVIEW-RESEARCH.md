# Can Marble re-render the canonical world from new viewpoints? (researched + verified 2026-08-26)

Four agents (API, exports, credits, and a skeptic who re-checked every source URL). Findings below survived the skeptic; each carries its source.

## Recommendation (verified)

Marble cannot give you a second view of world ae83acaa-df79-4e92-b31f-53af690d5deb: verified against the OpenAPI spec, the docs, and the live app bundle (release notes end 2026-04-02), there is no server-side render/camera/screenshot/video endpoint and no "new panorama from an existing world" operation; the only generation-time pano is the one you already hold, pano:depth_to_rgb is a fresh generation that will not match, and multi-image, Expand (2,000), pano edit (150 + 1,500) and Variations all create NEW worlds or new content rather than re-rendering this one. Spend zero credits: fetch the world's full_res splat (API GET /marble/v1/worlds/{id} -> assets.splats.spz_urls.full_res, or POST :export with {splats, ply}, which is explicitly free and cached; if the world lives in the app account instead, the SPZ 2M / PLY 2M download is a Standard+ plan feature with no credit line, and your Pro-level account already has it) and render the six views yourself on the L4. The sanctioned path is World Labs' own MIT Python client: load_spz (RDF->RUB) plus render_video/gsplat with your own Camera(height,width,fx,fy,cx,cy,camera_to_world) list, which needs only CUDA (no Vulkan ICD gamble) - forward, left, right, elevated, castle-approach and reverse are just six camera_to_world matrices, and you can also rasterise a fresh 360 by rendering a cube map; note it renders DC colour only (sh_degree=None), which is fine for consistent reference stills, or call gsplat.rasterization yourself with sh_degree set if you want view-dependence. splat-transform (MIT) is the one-liner alternative (--camera-pos/--camera-target/--camera-fov/--resolution, --projection equirect for a pano) but its renderer needs WebGPU-over-Vulkan, so only use it if the L4 container exposes a Vulkan ICD. Before trusting any frame, settle the coordinate frame with a known-up test camera: API SPZ is marble_raw_opencv (viewer applies a 180-degree X rotation; apply metric_scale_factor then ground_plane_offset then the Y/Z sign flip), whereas app-exported SPZ/GLB has been OpenGL by default since 2025-12-11, and the specs page's "+x left" wording looks like a doc typo. If you want Marble's own look without local tooling, Studio Record on the existing world (Compose -> Add scene -> your saved world) exports an un-enhanced MP4 with no credit line item, from which you can pull frames; avoid Enhance, which is a real 100 credits per second of video on Pro+, and download immediately because keyframes and enhanced video are lost on leaving the page. The HQ GLB you already have is a fallback for Blender/UE renders but the docs themselves say the mesh carries artifacts and the splat is the highest-fidelity representation, so render the splat.

## What this means for V2

- **No Marble operation renders a new view of an existing world.** The API has no render/camera/screenshot endpoint; multi-image, Expand, pano edit and Variations all create NEW worlds. Spending credits cannot buy consistent second views of THIS world.
- **Zero-credit paths for more views of the SAME world:** (1) render the HQ textured mesh we already own inside Unreal from the six `MarbleView_*` cameras (in the build now: `WL_EXTRA_ARGS="-WLShowTags=MARBLE_REFERENCE_ONLY -WLHideTags=UNREAL_PRODUCTION"`); (2) fetch the world's Gaussian splat (`GET /marble/v1/worlds/{id}` → `assets.splats.spz_urls`, or the explicitly free `:export {splats, ply}`) and render it on the L4 with World Labs' MIT Python client (gsplat, CUDA); (3) the web app's Studio › Record free camera (founder-side, un-enhanced MP4 has no credit line).
- **Preserve the splat with the world-bible** (provenance: it is the world's native representation); the mesh is a derived export.
